# Spelling challenge vocabulary

`words.txt` is the reviewable, alphabetized 2,000-word list. This is a difficult English spelling pack with academic, scientific and spelling-bee vocabulary, **not an official TOEFL list**. Most entries have at least ten letters; shorter entries are selected for irregular or difficult spellings. Elementary compounds, names, explicit/slang entries, and novelty words over twenty letters were excluded. Difficulty is editorial, not a standardized proficiency score. Inflected forms are separate questions where the recording distinguishes them.

`selection.json` maps each word to an existing U.S. English pronunciation file on Wikimedia Commons. `server/resources/spelling/words.tsv` supplies opaque IDs, canonical answers and accepted spelling alternatives. The server never includes the correct word in an active challenge snapshot. The public audio route uses an opaque ID; it is not intended to prevent determined inspection of audio-file metadata or the open-source catalog.

Recordings are unchanged. Their authors, source pages and licenses are in `audio-manifest.json` and `/api/spelling/credits`. Some older Commons pages lack structured author metadata; `author-overrides.json` records authors verified from the file description (and the self-upload history for epicurean). Two recordings whose descriptions disagreed with their names were excluded. Source metadata has been checked for the entire pack; recordings have not all been individually listened to by a human.

Refresh metadata with `python3 scripts/vocabulary/fetch-metadata.py`. This resumes from `.local/spelling-metadata/` and limits requests with pauses and backoff. It preserves the reviewed selection and existing opaque IDs. To change vocabulary, update selection and TSV together, retain 2,000 unique entries, and rerun metadata generation. The build rejects a missing or inconsistent catalog.

The TypeScript backend proxies allowlisted recordings from `upload.wikimedia.org` and marks them immutable for browser/Vercel CDN caching. It does not write to the deployment filesystem. Downloads are deduplicated per word and bounded to four concurrent recordings per instance and 4 MiB per recording. Audio is not stored in game state or database rows. First-time pronunciations require network access; the client allows retry/replay. The challenge starts immediately with the same word and shared fifteen-second deadline for everyone. Audio loads during that countdown; an uncached recording or browser autoplay restriction can reduce listening time. The replay button permits manual playback.

The selection was screened against [FrequencyWords by Hermit Dave](https://github.com/hermitdave/FrequencyWords), then manually filtered. The frequency data itself is not bundled. All included source recordings retain the individual licenses linked on the credits page.
